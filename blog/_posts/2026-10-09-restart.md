title: "Restarting pycc"
---

**Goal (unchanged):** compile type-annotated Python to native code that runs at
Rust-like speed, and report type mismatches at compile time instead of at runtime.

**What changes:**

1. **CPython interop is the base, not a later milestone.** Real Python code calls
   numpy, torch, VTK. A standalone binary without CPython is not useful for it, so the
   primary artifact is a CPython extension module (`.so` / `.pyd`) whose typed code runs
   natively and whose boundary with the rest of Python is `PyObject*`.
2. **Two modes.** `strict` (default): every type is known, `Any` is an error, values get
   native representations (`i64`, `f64`, fixed-layout structs, ndarray buffers).
   `non-strict` (per module): what cannot be proven typed compiles to C-API calls, like
   Cython - still correct, still compiled, just slower.
3. **No process apparatus.** pycc accumulated ~260 ADRs, coverage/perf/audit gates and
   governance tooling; most effort went there. pycc-next has a short `AGENTS.md`, one CI
   job (build + tests + conformance against CPython) and this blog.
4. **Ownership is an optimization, not a feature.** Borrowed references and escape
   analysis for small objects come after profiling; no ownership semantics in the
   language.

**Inspiration:** [ts-rust](https://github.com/pingdotgg/ts-rust) - an oracle (the
reference implementation) plus large real inputs beat a heavy process.

**Day 1:** imported the compiler crates from pycc@aab8cc6 (parser, HIR, type checker,
MIR, LLVM codegen, runtime) without docs, ADRs, scripts or gates. It builds against
LLVM 22; `fib` compiles, runs ~3x faster than CPython including process start, and
`fib("5")` is a compile error:

```
error[T0021]: argument 1 of `fib` expects `int`, got `str`
```
