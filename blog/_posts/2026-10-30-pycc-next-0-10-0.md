0.10.0 is out. This milestone was about **trust**: exact CPython error texts, native
`str`-keyed dicts, the class work 0.9 deferred, and speed numbers that come from a CI job
anyone can rerun, not from my shared VM. **Four of five accept items are met. The speed
goal for the template and Markdown engines is not.** Here's all of it.

## 🏁 The scorecard

| goal | target | result |
|---|---|---|
| 1. exact error texts | CPython 3.13's `TypeError`/`AttributeError` word for word; fuzzer finds 0 in 30 min | ✅ **met**: 2996 fuzzed programs, 0 findings |
| 2. native `str`-keyed dicts | native where they never escape, CPython's `dict` everywhere CPython can see | ✅ **met** |
| 3. pystache and mistune | their own benchmarks >= 1.2x CPython | ❌ **not met**: **0.63x** and **0.83x** |
| 4. trustworthy numbers | every published speed number from a CI `bench` run | ✅ **met**: this post cites run 41010653642 |
| 5. deferred class work | cross-module subclasses and exception classes native in a package | ✅ **met** |

## 📏 Numbers you can check

Until now, my speed numbers came from a shared machine I couldn't control, so they jumped
around from run to run. Now there's a **`bench` workflow**. It runs on release tags, every
week, and on demand. Each run is a fresh process, CPython and pycc-next alternate, and the
result is a median with min and max, labelled with the runner's CPU.

And CPython is no longer the only thing I compare against. CPython stays the
**correctness oracle**. **Cython 3.3.0 and mypyc** now build the same unmodified sources
and are timed the same way. Everything below is from
[run 41010653642](https://github.com/rotnov/pycc-next/actions/runs/41010653642), Intel Xeon
Platinum 8370C, medians of 11 interleaved runs.

| program | CPython | pycc-next | vs CPython | vs Cython | vs mypyc |
|---|---|---|---|---|---|
| fib | 0.258s | 0.011s | **22.6x** | 12.99x faster | 2.56x faster |
| sieve | 1.109s | 0.047s | **23.6x** | 16.15x faster | 2.92x faster |
| mandelbrot | 1.620s | 0.056s | **29.1x** | 2.23x faster | 1.24x faster |
| nbody | 2.606s | 0.077s | **33.9x** | 63.48x faster | 29.46x faster |
| spectral_norm | 1.194s | 0.017s | **69.4x** | 80.19x faster | 5.21x faster |
| collections_bfs | 1.100s | 0.138s | **8.0x** | 7.49x faster | 5.23x faster |

Rust (`-O`) still wins all of them: pycc-next is **1.10x to 2.71x slower**.

## 📦 Real packages: the wins and the losses

| package workload | vs CPython | vs Cython | vs mypyc |
|---|---|---|---|
| pypng `read()`, five filters | ✅ **15.1x** | 10.8x faster | does not compile |
| diff-match-patch `diff_main` | ✅ **12.1x** | 11.1x faster | does not compile |
| tomli `loads` x100 | ✅ **1.70x** | 1.32x faster | ❌ **1.39x slower** |
| mistune `html` x20 | ❌ **0.83x** | Cython's build fails the suite | does not compile |
| pystache benchmark x1000 | ❌ **0.63x** | ❌ **1.82x slower** | does not compile |

Two honest notes on that table:

- **mypyc beats me on tomli.** Its typed code wins on tomli's string scanning.
- **Cython beats me on pystache.** Cython keeps CPython's own objects and runs a bit
  faster than the interpreter (1.14x). pycc-next pays to cross the boundary between
  compiled code and CPython objects, and on pystache that cost dominates.

pydantic, built whole: model definition **0.81x**, `model_json_schema()` **0.83x**.

## 🧱 What shipped

- 🎯 **Exact error texts.** Calling a compiled function wrong raises CPython's
  exact `TypeError`. That covers `missing 1 required positional argument: 'x'`,
  `takes from 2 to 3 positional arguments but 4 were given`, and `Did you mean 'by'?`.
  The differential fuzzer now generates broken calls on purpose and compares the messages.
- 📚 **Native `str`-keyed dicts.** A dict a function builds and never lets escape is
  native. Any dict CPython can see stays CPython's `dict`, accessed through the dict API
  under an exact-type guard. That way identity, views, pickling and `repr` behave exactly
  as in CPython. A compiled `d['raw']` on a received dict went from **275 to 179
  instructions**.
- 🧬 **Cross-module subclasses.** `class Square(Shape)`, with `Shape` imported from
  another module of the package, is compiled natively. `Shape`'s compiled methods run
  `Square`'s overrides. Each class gets one record, so a class test is a single pointer
  compare.
- 💥 **Exception classes with their own members** can derive from another module's
  exception class. CPython creates the class and pycc-next compiles its methods. I also
  built a fully native layout for them (PEP 697) and **measured it: 2.5x slower on raise
  and catch, 1.5x slower on attribute reads.** It's deleted. 🗑️
- 🥒 **Pickling** of compiled class instances at every protocol, including
  `copy.deepcopy` and Python subclasses with their own hooks.
- 🔑 **`key=` functions run exactly when CPython runs them.** That covers `sorted`,
  `min`, `max` and `.sort`, including exceptions raised in the middle.
- ⏱️ **Faster package builds.** Mistune's 38-module build in CI went from **9.5 s to about
  6.1 s**, and the extension comes out byte-identical.

## 🧪 Why pystache is still slow

I measured instructions per round for pystache's own benchmark: **CPython 505k, pycc-next
582k.** Native dicts weren't the fix. Neither package spends its time in dicts it creates
and keeps to itself. Their dicts are returned, appended or passed on, so CPython can see
them and they must stay CPython dicts. What's left is the boundary between compiled code
and CPython objects, plus CPython's own regex engine, which I can't compile away. The
[v0.10 roadmap](https://github.com/rotnov/pycc-next/blob/main/docs/roadmap/v0.10.md) lists
the remaining levers with estimated savings. **None of them reaches 1.2x on its own**, so I
shipped without this goal rather than keep chasing it.
