Two days after 0.2.0, **0.3.0 is out**. This one is about the code people actually write:
several files, `import`s, dataclasses, `Counter`, `itertools`. And one package straight off
PyPI.

## 🏁 The scorecard

| goal | target | result |
|---|---|---|
| multi-module | `import m`, packages, relative imports, one compiled unit | **native, `--non-strict` and `--ext`; cross-module calls are direct calls** |

## 📦 A real package, not a demo

I picked **diff-match-patch**: Google's diff/match/patch algorithms, Apache-2.0, pure Python,
and it ships its own test suite. Every module builds unchanged with
`pycc build --ext --non-strict`. All 40 functions and methods compile, none fall back to
CPython, and its 28 tests pass against the compiled `.so` files. CI downloads the pinned sdist,
checks its hash, builds, swaps the extensions in, and runs the suite on every push.

The honest part: its speed test runs **1.7x faster, not 30x**. The package has no type
annotations, so its text parameters stay CPython `str` objects and most of the work still goes
through CPython's string machinery. Untyped code gets correctness first and modest speed. Typed
code gets the 20-680x numbers below.

## 🧩 Imports that are really imports

`import helper`, `from pkg.sub import f`, `from ..util import g`, `__init__.py`: each
module keeps its own namespace, its body runs once in CPython's import order, and
`helper.add(1, 2)` compiles to a direct native call. Two modules can both define `main`. An
uncaught exception prints as `helper.E: msg`, like CPython. Circular imports are refused with a
clear error for now.

## 🧰 The stdlib you actually use

- `@dataclass` with defaults, `field(default_factory=...)`, `order=True`, `frozen=True`
- `Enum`, `IntEnum`, `functools.cache` / `lru_cache`
- `deque`, `Counter`, `defaultdict`
- `itertools.product/permutations/combinations/accumulate/chain/islice/groupby/...`, as lazy
  native iterators

A BFS over a grid with `deque` runs **6.8x faster than CPython**. A word count with `Counter`
is about 4x faster.

## 🛡️ What review caught

Every push went through security review, and it earned its keep:
- a `defaultdict` factory that drops the last reference to its own dict (use-after-free);
- a module name that could reach generated C unescaped;
- a `__str__` with the wrong signature that the checker skipped but codegen still called.

My own pre-release pass also found a **leak**: every fresh `str` passed to a CPython call lost
about 40 bytes. `json.dumps(str(i))` in a loop grew by megabytes. It's fixed, and 10 new
constant-memory probes guard that boundary.

## 🔭 Next

Untyped code is correct but only modestly faster, so the next big lever is inferring native
`str` and `list` types through untyped functions. And there are still 23 non-strict statements
that run in CPython. The roadmap is in `docs/ROADMAP.md`.
