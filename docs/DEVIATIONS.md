# Deviations from CPython

Behavior that differs from CPython 3.13 on purpose or because it is not implemented yet.
Each entry: what differs, why, and whether it is planned to go away.

| Behavior | pycc-next | CPython | Status |
|---|---|---|---|
| An `int` beyond 63 bits stored in a container (`list[int]`/`set[int]`/`dict` element) or used as a slice bound | raises `OverflowError` (element) or `IndexError` (list slice bound) at run time; a literal in those positions is compile error `T0051` | stores it / clamps the bound | not implemented yet; arithmetic, comparison, conversion, printing and the `--ext` boundary are arbitrary precision, and an index or repeat count raises CPython's own `IndexError`/`OverflowError` |
| `int ** negative int` | raises `RuntimeError` (`**` is typed `int -> int`); a negative int *literal* exponent (`10 ** -10`) is a `float`, as in CPython | returns a `float` | to be fixed in the type checker |
| `**` or `<<` producing more than 2**36 bits | raises `OverflowError: too many digits in integer` | raises `MemoryError` (or runs out of memory) | on purpose: pycc has no `MemoryError` |
| `str()`/`print` of an `int`, or `int()` of a decimal `str`, with more than 4300 digits | always raises `ValueError` (the default limit) | limit adjustable with `sys.set_int_max_str_digits()` | `sys` is not compiled |
| An `--ext` module's attribute rebound from Python (`mod.f = g`) | compiled callers inside the module still call the original `f` | module-level lookups see `g` | on purpose: calls between compiled functions bind at compile time (a function defined once and never assigned is called directly) |
| `print`/`str()`/f-string of a list whose elements are class instances | compile error `C0001` | calls each element's `__repr__` | not implemented yet |
| A container element (or dict value) other than `int`/`float`/`bool`/`str`/class instance/list, tuple, dict or set of those (e.g. `list[None]`, `list[int \| None]`), a dict key or set element that is not `int`/`float`/`bool`/`str`/a tuple of those (sets also hold class instances) | compile error `T0034`/`T0036`/`T0038`/`T0039` | runs | not implemented yet |
| Unsupported but valid Python (e.g. a nested function used as a value while a variable it reads may still change, a lambda used as a value) | strict: compile error `C0001` naming the construct; non-strict: the enclosing top-level function, class or statement runs in CPython (`--report-fallbacks`) | runs | each is a gap, never silent miscompilation |
| Non-strict fallback: compiled code reads a module global that fallback code binds, before it is bound | `KeyError: 'name'` (the read is a lookup in the module dict) | `NameError: name 'name' is not defined` | to be fixed |
| Non-strict fallback: a type error in non-strict code (`T00xx`) | the statement falls back and runs in CPython (which raises or not at run time) | runs | by design: non-strict code has CPython's semantics where pycc cannot prove types |
| Non-strict fallback in a module imported by the entry module | the diagnostic is reported; only the entry module falls back | runs | not implemented yet |
| Non-strict fallback: a class in a native (embedded) build with any fallback code | the class falls back too (an embedded `__main__` publishes compiled functions, not classes, and an instance may reach fallback code through any value) | n/a | not implemented yet |
| Compiled code (not fallback code) raising an uncaught exception | prints only the last traceback line | prints the full traceback | not implemented yet |
| Non-strict mode: a CPython object used as a list, tuple or `str` index, a list store's index or a `range()` argument | read through `__index__`, as CPython does; a `range()` argument beyond 2**61 raises `OverflowError` | `range()` takes any `int` | rare: a compiled loop never counts that far; a sequence index of any size raises CPython's own `IndexError` |
| `open(0)` (the builtin `open`, file descriptor 0) | standard input itself, sharing one buffer with `input()` and `sys.stdin`; the descriptor stays open | a second text file over descriptor 0 with its own buffer, closing the descriptor when collected | rare: only a program that mixes `open(0)` with `input()` can tell |
| Non-strict mode: `o.sort(key=f)` / `sorted(o, key=f)` / `min(o, key=f)` on a CPython object `o` | the key function runs on each element while `o` is iterated, then the keys are sorted (or compared) by CPython; a receiver that is not a `list` raises after the keys are computed (`AttributeError`, or `TypeError` for an object with its own `sort`) | `sorted` iterates `o` fully before the first key call; `o.sort` looks the method up first | rare: only a key function with side effects, or an iterable that observes them, can tell |
| Non-strict mode: a CPython object passed to a typed `int`/`float`/`bool`/`str` parameter (or returned as one) | checked at the boundary: `TypeError: f() argument 1 must be int, not str`; an `int` for a `float` slot becomes a `float` | the body runs with the object and fails (or not) later | by design: typed code keeps native representations |
| Strict native build: an unannotated function or method (not `__init__`) | compiled with the one signature its call sites imply, like a private helper; `T0001` when the call sites disagree, none types a parameter, or the body does not pin the return | takes any value | by design (a strict-mode rule since v0.2): a native program is closed, so every caller is known. An `--ext` module's public functions still need annotations (`T0001`) |
| Non-strict native build: an unannotated `def`, `name = lambda ...` or method that nothing in the entry module mentions (and the module reaches nothing by string: no `getattr`, `globals`, `eval`, ...) | not compiled | binds the name | by design: it can never run, so the program's behavior is the same; strict mode still checks it (`T0001` when nothing types it) |
| Non-strict native build: an unannotated function called from compiled code with values of one type | compiled with that type (inferred from its call sites like a private helper's) | takes any value | by design; a function fallback code also calls is compiled with objects instead (or runs in CPython), and an `--ext` module's unannotated functions take objects |
| An `int` beyond 63 bits held by a `tuple` (`t = (x * 2, 1)`, `q, r = divmod(big, 7)`) | the tuple's reference to it is never released, so a long loop building such tuples grows memory | freed with the tuple | not implemented yet (D-182); temporaries, names, parameters, call arguments and returned values are reference counted (#625) |
| Non-strict mode: a name holding a native container (`xs: list[int]`, or a list built natively) passed into an `object` slot | compile error `T0021` (a display such as `f([1, 2])` and a local that only ever flows into objects are built as CPython containers instead; a fresh list nothing else holds yet -- a comprehension, `list(...)`, `sorted(...)`, `s.split()`, a concatenation, repetition or slice of scalars, `str`s, tuples of those or instances -- is copied into one, as an argument, a stored value or an operand of an operator on an object; a comprehension whose elements are objects builds a CPython list or set) | the same list object is shared | a copy would break aliasing; refused rather than copied |
| `reversed(xs)` | returns a new list | returns a lazy iterator | equal output wherever the result is only iterated, indexed by `list()` or printed via `list(...)` |
| `str` character classes beyond ASCII (`isdigit`, `isspace`, `split()` whitespace, case mapping) | Rust's Unicode tables | CPython's Unicode database | they agree on ASCII; rare differences beyond it |
| `sum()` of an empty `list[float]` | `0.0` | `0` (the int start value) | not planned until `sum` gets a start argument |
| `map(f, xs)` / `filter(f, xs)` | build a list eagerly (`pycc_ast::desugar`) | return lazy iterators | equal output wherever the result is iterated, unpacked or passed to `list`/`sum`/...; printing the map object itself differs |
| `sys.stdin.buffer.readline` aliased by a module-level name (`input = sys.stdin.buffer.readline`) whose every call is converted to numbers at once (`int(input())`, `float(input())`, `map(int, input().split())`, `[int(x) for x in input().split()]`) | read as text, natively | reads `bytes` | equal for every input `int()`/`float()` accept as ASCII; a non-ASCII digit (`int(b"\xd9\xa1")`) is accepted from text but refused from `bytes`. Any other use of `sys.stdin.buffer` is `bytes`: CPython's own in non-strict mode, refused in strict mode |
| `sys.stdin`/`sys.stdout` stream calls (`readline`, `read`, `readlines`, `write`, `flush`) and `sys.setrecursionlimit` | native (`setrecursionlimit` is a no-op: compiled code recurses on the native stack) | `sys` module objects | same output; other `sys` attributes still go through CPython. Whenever CPython is present (`--ext`, or an embedded build) every native read and write, `print` and `input()` included, goes through CPython's `sys.stdin`/`sys.stdout`, so native and Python-side I/O share one buffer |
| A reference cycle between lists, dicts, sets and/or class instances (`a.other = b; b.other = a`, `xs.append(xs)`), including one that passes through a CPython object an instance's `object` attribute holds | never freed: compiled `str`, `list`, `dict`, `set` and class instances are reference counted with no cycle collector, so a cycle's objects keep each other alive until the process exits | the cycle collector frees it once unreachable | on purpose for this release; a non-cyclic object is freed at the moment its last reference goes, exactly when CPython frees it |
| `__del__` on a compiled class | never called | called when the reference count reaches zero | not implemented yet: a compiled class's `__del__` is an ordinary method nothing calls |
| Exception objects (a raised or caught exception and its message) | leaked until the process exits | freed | not reference counted yet; bounded by the number of exceptions raised. Every `str`/list/dict/set/instance temporary live when an exception unwinds is released |
| `d.keys()`, `d.values()`, `d.items()` | a new list (a snapshot) | a live view (`dict_keys([...])` when printed) | equal output wherever the result is iterated, indexed through `list(...)`, sorted or measured; printing the view itself differs |
| `str` hashes in an `--ext` module when `PYTHONHASHSEED` is unset | compiled code draws its own random SipHash key, so a set of `str` built natively and one built by the host interpreter may iterate in different orders within one process | one per-process key | both are randomized, so no program can depend on either order; with `PYTHONHASHSEED` set, `str` hashes (and a set of `str`'s iteration order) are exactly CPython's |
| `==`/`!=` between containers of class instances (`set[C]`, `list[C]`, a dict with `C` values, nested) | compile error `T0021` | compares elements with the class's `__eq__` | not implemented yet |
| Replacing a `dict`'s keys while iterating it without changing its size (`del d[k]; d[k + 10] = 0` inside `for k in d`) | iteration continues over the changed table | raises `RuntimeError: dictionary keys changed during iteration` once it runs past the keys it started with | not implemented yet; a change of size raises CPython's `RuntimeError: dictionary changed size during iteration` (`Set changed size during iteration` for a set) at the next step, as in CPython |
| A name rebound to an unrelated value (`n = input()` then `n = int(n)`) | each live range is its own variable (`pycc_ast::desugar::webs`), so the earlier value is released when its own variable is next rebound or its scope ends | the earlier value is released at the rebinding | on purpose: it is what lets each live range have its own type; output is the same, only the moment a value is freed differs |
| A dict comprehension with more than one `for` or `if` clause | every key and value is evaluated, then the dict is built from the pairs (`pycc_ast::desugar::helpers`) | each key is hashed and stored as soon as its value is evaluated | equal output unless a key's `__hash__`/`__eq__` has a visible effect or raises part-way |
| A generator object | the generator protocol (`next()`, `send()`, `throw()`, `close()`, `yield` as a value, `return value`, `yield from` delegation) without the `gi_*` attributes; an `--ext` export returns a CPython iterator of type `generator` supporting iteration only | a generator object with every attribute | not implemented yet |
| `next()` resuming a `yield` expression whose generator's send type excludes `None` (`Generator[int, int, ...]`, `x = yield`) | raises `TypeError` (`x` is typed `int`) | `x` is `None` | on purpose: the send type is what the program declared; a statement `yield v` takes `next()` as usual |
| `gen.send(None)` to a generator whose send type excludes `None` (`Generator[int, int, ...]`) | `T0021` at compile time (`--non-strict`: the call runs in CPython); prime such a generator with `next(gen)` | legal; a `yield` expression receives `None` | on purpose, like the row above |
| `yield from` a generator that had already finished, where the delegate's return type excludes `None` | raises `TypeError` | the expression is `None` | on purpose, like the row above |
| `e.value` of `except StopIteration as e` | typed as the return type of the generators the `try` body itself resumes (`next(g)`, `g.send(v)`, `g.throw(e)`); `C0001` when it has none or they disagree, `TypeError` at run time when the caught `StopIteration` carries no value but that type excludes `None`, or a value of another type (raised by a generator some call in the body resumed) -- the value is never reinterpreted | any object | on purpose: `StopIteration.value` has no static type of its own |
| `gen.close()` of a generator that returns a value on `GeneratorExit` | returns `None` | returns the value (3.13) | not implemented yet |
| A generator that catches `GeneratorExit` and yields again while it is released (not by an explicit `close()`) | `RuntimeError` reported, the frame freed without releasing its locals | `RuntimeError` reported, the frame cleared | the locals of that one frame are leaked |
| An unfinished generator in a module global of an `--ext` module | never closed | closed at interpreter shutdown | not implemented yet; a native program closes its generator globals at exit in assignment order, and `del name` closes one at once, as in CPython |
| An `--ext` function or method with a default, a positional-only or keyword-only parameter, `*args` or `**kwargs`, called from Python | a Python function with the declared signature (a method: its type's method row calls one), which calls the compiled body (`pycc_ast::desugar::ext_signatures`); a `*args`/`**kwargs` element, or the argument of a parameter whose default is not a literal, of the wrong type raises `TypeError` (as a scalar argument does), and a `bool` element of `*args: int` arrives as an `int` | the uncompiled function | not implemented yet for a constructor with keyword-only parameters, `*args` or `**kwargs` (it takes its flattened parameters positionally), a method name two classes of the module share, an element type other than `int`/`float`/`str`/`bool`, and a non-literal default of a non-scalar parameter: those keep the boundary's refusal |
| A module-level function used as a value (`fs = [add]`, `print(add)`) | each use makes a new function object, so two uses print different addresses; `is` between function values is compile error `C0001` and `==` is `T0021` | one object per `def`, compared by identity | not implemented yet; a nested function's value is one object per evaluation of its `def`, as in CPython |
| A function with a `*args`, a keyword-only parameter, a `**kwargs` or a default that is not a literal, used as a value or called from another module | takes its flattened parameters (`pycc_ast::desugar::signatures`): the positional ones, then `*args` as a list, the keyword-only ones, then `**kwargs` as a dict, all positional and without defaults | the declared signature | not implemented yet; every call in its own module binds the declared signature |
| A call of a function with only positional parameters and literal defaults that cannot bind (too many or too few arguments, an unknown or doubled keyword) | compile error `T0021` | `TypeError` when the call runs | on purpose (a static type error); a call with `*seq`/`**mapping`, and any call of a function with `*args`, keyword-only parameters or `**kwargs`, raises CPython's own `TypeError` at run time |
| `*args` inside the function | a list that prints, compares and slices as a tuple; mutating it (`args.append(x)`) works; `*args: bool` prints as a list | a tuple | the method and item-assignment calls a tuple lacks are not refused yet |
| `f(k=1, **{"k": 2})`, a keyword given both explicitly and by a mapping | `TypeError: __main__.f() got multiple values for keyword argument 'k'`, always naming the module `__main__` | names the function's real module | rare |
| An element read from a typed numpy array (`a[i]`, `a[i, j]`, `for x in a` with `a: NDArray[np.float64]`, `NDArray[np.int64]` or `NDArray[np.bool_]`) | a Python `float`, `int` or `bool`: `[a[0]]` prints `[1.0]`, arithmetic on `int64` elements is arbitrary precision (no wraparound, no `RuntimeWarning`), a float division by zero raises `ZeroDivisionError` | a numpy scalar (`np.float64`, `np.int64`, `np.bool`): `[a[0]]` prints `[np.float64(1.0)]`, `int64` arithmetic wraps with a `RuntimeWarning`, division by zero gives `inf`/`nan` with a warning | on purpose: elements compile to machine values. Storing an `int` outside `int64` into an `int64` array raises numpy's own `OverflowError: Python int too large to convert to C long` |
| A value bound to a typed array parameter or name (`def f(a: NDArray[np.float64])`, `x: NDArray[np.int64] = obj`) that is not a `numpy.ndarray` of that dtype and number of dimensions | `TypeError: expected numpy.ndarray[float64, 1-D], got list` (`... got a 2-D array`, `... got an array of dtype int64`) at the binding | runs until an operation fails, or computes with the other dtype | on purpose: checked once where a value enters a typed slot, so element access needs no check. The number of dimensions of `NDArray[np.float64]` is inferred from how the name is indexed (`a[i, j]`, `a[i][j]`, `n, m = a.shape`); with no evidence it is 1 |
| A typed array changed in place by CPython code while compiled code holds it, to another dtype or number of dimensions (`a.__setstate__(...)`, `a.resize((2, 3), refcheck=False)` of a 1-D array) | the next compiled access raises `TypeError: expected numpy.ndarray[float64, 1-D], got an array of dtype bool` (a new shape or data buffer of the same dtype and dimension count is simply used) | the access uses the array as it now is | on purpose: an array is re-checked, and its shape, strides and data pointer re-read, after any call that may run CPython code, so a loop that calls none keeps them in registers |
| `a[True]` on a typed array; a tuple index containing a slice (`a[:, j]`) | a `bool` index is compile error `T0021`; `a[:, j]` is compile error `C0001` in strict mode and runs in CPython under `--non-strict` | boolean mask indexing; a view | `bool` refused on purpose (numpy reads it as a mask). A plain slice `a[1:3]` works (a CPython call returning a view); slices are not compiled natively yet |
| A generator expression reading a local its function rebinds before the generator has run (neither passed straight to `any`/`all`/`next`/`sum`/... nor reading only parameters and once-assigned variables) | compile error `C0001` (or falls back in non-strict mode) | reads the variable's value when each element is produced | not implemented yet: a compiled generator expression receives its enclosing variables by value |
