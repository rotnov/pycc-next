# Deviations from CPython

Behavior that differs from CPython 3.13 on purpose or because it is not implemented yet.
Each entry: what differs, why, and whether it is planned to go away.

| Behavior | pycc-next | CPython | Status |
|---|---|---|---|
| An `int` beyond 63 bits used as a list slice bound | raises `IndexError` at run time | clamps the bound | not implemented yet; containers hold big `int`s, and arithmetic, comparison, conversion, printing and the `--ext` boundary are arbitrary precision, and an index or repeat count raises CPython's own `IndexError`/`OverflowError` |
| `int ** negative int` | raises `RuntimeError` (`**` is typed `int -> int`); a negative int *literal* exponent (`10 ** -10`) is a `float`, as in CPython | returns a `float` | to be fixed in the type checker |
| `**` or `<<` producing more than 2**36 bits | raises `OverflowError: too many digits in integer` | raises `MemoryError` (or runs out of memory) | on purpose: pycc has no `MemoryError` |
| An unfiltered `[x for x in range(...)]` (identity element) over more elements than a C `ssize_t` counts | raises `OverflowError: Python int too large to convert to C ssize_t` before iterating, as `list(range(...))` does in both | iterates until it runs out of memory | on purpose: it is the form `list()`, `tuple()` and `sorted()` of a `range` compile to; no list that long can be built |
| `str()`/`print` of an `int`, or `int()` of a decimal `str`, with more than 4300 digits | always raises `ValueError` (the default limit) | limit adjustable with `sys.set_int_max_str_digits()` | `sys` is not compiled |
| An `--ext` module's attribute rebound from Python (`mod.f = g`) | compiled callers inside the module still call the original `f` | module-level lookups see `g` | on purpose: calls between compiled functions bind at compile time (a function defined once and never assigned is called directly) |
| A container element (or dict value) other than `int`/`float`/`bool`/`str`/class instance/list, tuple, dict or set of those, or a `T \| None` of an `int` or of a `str`/container/instance (e.g. `list[None]` that nothing else is stored in, `list[float \| None]`), a dict key or set element that is not `int`/`float`/`bool`/`str`/a tuple of those (sets also hold class instances) | compile error `T0034`/`T0036`/`T0038`/`T0039` | runs | not implemented yet |
| Unsupported but valid Python (e.g. a nested function used as a value while a variable it reads may still change, a lambda used as a value) | strict: compile error `C0001` naming the construct; non-strict: a nested `def` or `lambda` runs in CPython alone, its body compiled (see the nested-function row), otherwise the smallest enclosing function or method runs in CPython; a top-level statement outside any function, and a method of a compiled class that cannot be attached to it (see the attached-method row), take their class or statement along (`--report-fallbacks`) | runs | each is a gap, never silent miscompilation |
| A module-level name bound both by a `def` and by another binding (`f = g`, `for f in ...`, `import ... as f`, `except ... as f`) (issue #1) | strict: compile error `C0001` at the other binding; non-strict: that binding, and every `def` of the name, run in CPython (as does a `def` whose name fallback code rebinds -- a `def` or lambda in a block, a `global` store -- and a function defined more than once that fallback code reads), so compiled callers read the name from the module's namespace | runs | not implemented yet: a compiled `def` and a variable are two homes for the name; a function defined more than once (`def` only) stays compiled, and a value of it (`g = f`) is the definition of that moment |
| Non-strict fallback: a type error in non-strict code (`T00xx`) | the statement falls back and runs in CPython (which raises or not at run time) | runs | by design: non-strict code has CPython's semantics where pycc cannot prove types |
| Non-strict fallback in a module imported by the entry module | the diagnostic is reported; only the entry module falls back | runs | not implemented yet |
| Non-strict fallback code (in the entry module) that uses a project module or a name imported from one | the original diagnostics are reported: the program does not fall back | runs | not implemented yet: project modules are compiled into the program, so CPython cannot import them |
| A circular import between project modules (`a` imports `b`, `b` imports `a`) | runs as in CPython, `b` seeing the names `a` bound before `import b` and `from a import x` of a name not bound yet raising CPython's `ImportError`; compile error `C0001` for a module-level read `a.x` of a name not bound yet (CPython's `AttributeError`) and for reaching a class or type alias of `a` from `b`; compile error `E0108` when a module imports the entry module back; a module-level read in `b` of a name such a failing `from a import x` binds is `C0001`; a function of `b` run during the import that reads `a.x` before `a` binds it raises `NameError: name 'x' is not defined` (CPython: `AttributeError: ... has no attribute 'x'`), and so does one that calls `a.f()` before `a` defines `f` | runs, with the partially initialized module visible; the entry module imported back is a second copy (`__main__` and its own name) | not implemented yet: classes are copied into each importer when it is lowered, before `a` is; the entry module is linked once; a read inside a function cannot tell `a.x` from `a`'s own `x` at run time |
| A project module used as a value (`print(m)`, `x = m`), an assignment to its attribute (`m.x = 1`), or rebinding a name a project import binds (`from m import f` then `f = g`) | compile error `C0001`; reading `m.x` and calling `m.f(...)` work | runs | not implemented yet |
| `import m` / `from m import x` of a project module inside an `if`/`try` block or a function | compile error `C0001` | runs when reached | not implemented yet: a project module's body runs at its first module-level import |
| A name a project module binds by importing a CPython module (`m.json` after `import json` in `m`) and a name the entry module defines | share one global: the entry's definition of that name is `C0001` | separate namespaces | not implemented yet; a project module's own definitions have their own namespace |
| `chr()` of a surrogate code point (`0xD800`-`0xDFFF`) in strict mode, and a CPython `str` holding a lone surrogate passed to a `str` parameter | `ValueError: chr() arg not in range(0x110000)` / the boundary refuses the `str` | a one-character `str` holding the surrogate | by design: pycc's `str` is UTF-8; non-strict mode runs `chr()` in CPython |
| `--ext`: a module-level variable or import | an attribute of the module, each compiled store copied onto the module object (`src/ext_globals.rs` in strict mode, the fallback rewrite in non-strict mode); in strict mode only a global whose annotation or module-level value is evidently native (a literal, arithmetic on such values, a call of a function annotated to return one, `str()`/`int()`/`len()`) is published: an import, a CPython object, an instance or enum member (which cross as CPython objects), a native `list`/`dict`/`set`, a name also bound by a `for`/`with` target, `del`, a walrus or a `match` capture, every global of a `--foreign-relative-imports` build, and every global when an `if`/`for`/`while`/`try`/`with`/`match` statement before the module's first simple statement could run a copy, are not attributes; a Python assignment to the attribute (`mod.LIMIT = 3`) is not seen by compiled code | every global is a module attribute | a copy cannot share a native container with Python code, and a second reference to a CPython object would be visible (`sys.getrefcount`, when it is freed) |
| Non-strict: a class attribute initialized with an expression that is not a literal (`P = re.compile(...)`) | evaluated once where the class statement runs and read through a hidden global; not an attribute of the published class from Python; an assignment to it (`self.P = x`, `C.P = x`) falls back | a class attribute | not implemented yet |
| Strict: a class attribute the program assigns through its class (`C.count += 1`) | a module variable while every access spells `C.count`: an `--ext` module's published class keeps the initial value when Python code reads `C.count`; an access through an instance or a subclass (`self.count`, `D.count`), or a write in a class body, keeps the class attribute a constant and the write is refused | the class attribute itself | not implemented yet: a class attribute is folded into each read, with no storage of its own |
| Non-strict `--ext`: Python storing an `int` into an instance attribute pycc inferred as `float` (`obj.timeout = 0`) | stored as the `float` `0.0` | stores the `int` | rare: only code that reads the type or `repr` back can tell; strict mode refuses the `int` (D-086) |
| `--ext --foreign-relative-imports`: a module's `__name__` | the dotted name its `__init__.py` files spelled when it was built (`pkg.mod`) | the name it was imported under | the same unless the package is renamed or imported from another root |
| Non-strict `--ext` package `__init__.py`: an import of a sibling module (`from .core import X`) | runs in CPython at its place in the module body (`--report-fallbacks` lists it) | an import | by design: the names it binds are CPython objects either way |
| `--ext` build of a program of several modules | the extension module holds the entry module's own definitions; the project modules it imports are compiled in, not attributes of it (`main.helper`, a from-imported `main.f`) and not in `sys.modules`; an instance of a dependency's class crosses the boundary as an object of type `<module>.<Class>` (`geo.P`) whose class is not reachable from Python, so it cannot be constructed there | every module is a module object | by design for this release; `--foreign-relative-imports` builds one extension per module instead |
| Non-strict fallback: a class in a native (embedded) build with any fallback code | the class falls back too (an embedded `__main__` publishes compiled functions, not classes, and an instance may reach fallback code through any value) | n/a | not implemented yet |
| Non-strict: a class whose statement runs in CPython (a CPython base, a metaclass, a decorated method, a class attribute pycc does not compile, a method that falls back, any class of an embedded build with fallback code) | CPython creates the class; each method's `def` forwards to a compiled function (`__pycc_liftN_name__`) holding its body, so a traceback through it shows one extra Python frame, and `self` is the CPython instance, its attributes read and stored through the object protocol | the methods are Python functions | by design: the class is CPython's, its method bodies compiled |
| Non-strict `--ext`: a published native class (compiled, with no CPython base) | not subclassable from Python code outside the package (`TypeError: type '...' is not an acceptable base type` at class creation, also for a class created dynamically); a class the module's own fallback code or a sibling module of the package subclasses is created by CPython instead (`--report-fallbacks` names the subclass) | subclassable | not implemented yet: a compiled method calls its class's methods statically, so a Python override would not be seen |
| Non-strict `--ext`: a method of a compiled class that cannot compile (the *attached* method) | a CPython function installed as the class's method; it reads and stores only attributes the class publishes (other methods, properties, scalar, object or instance fields), takes positional parameters only, and is not a generator, `__init__`/`__new__`, decorated, or a user of `super()`/`__class__` -- otherwise the whole class runs in CPython | the method | by design: a compiled instance exposes only those fields to CPython |
| Non-strict: `with` on a context manager | compiled as PEP 343 prescribes, except that `__enter__`/`__exit__` are looked up on the object (not its type) and an exception other than an `Exception` (a `KeyboardInterrupt`, `SystemExit`) leaving the body calls `__exit__(None, None, None)` instead of passing it; `async with` is not compiled (C0001; it runs in CPython) | `type(m).__enter__`, every `BaseException` passed | not implemented yet |
| Non-strict: a starred display of objects (`[*a, *b]`, `{*a}`, `{**a, 'k': v}`) | built with `list()`, `set()` and `dict()` calls, so unpacking a non-iterable raises `TypeError: 'int' object is not iterable` instead of `Value after * must be an iterable, not int` | its own messages | rare: only the message of a failing unpacking differs |
| A compiled generator handed to CPython (`--non-strict`: `contextlib.contextmanager`, `next(g)`) | `send()` takes only `None` (`TypeError` otherwise); an embedded native program does not publish generators, so a generator CPython code receives runs in CPython | a generator object | not implemented yet |
| `from __future__ import annotations as x` | binds nothing (the feature still applies) | binds `x` to the `__future__._Feature` | rare: nothing reads the alias |
| Non-strict: a nested `def` or `lambda` that CPython creates for a compiled enclosing function (one used as a value, `--report-fallbacks` says `lifted:`) | its decorators, defaults, `__name__`, `__qualname__`, `__doc__` and `__wrapped__` are CPython's; its code forwards to a compiled function (`__pycc_lift_nestN__`) holding its body, so `__code__.co_freevars` is `('__pycc_cells',)` and `__closure__` holds one cell (a tuple of the captured variables' cells), and a traceback through it shows the forwarder's frame; a `def` or `lambda` inside a comprehension, or one holding a nested `def` or `lambda` of its own whose body fails to compile, takes its enclosing function to CPython | the function's own code, one free variable per captured name | by design: CPython creates the function, its body compiled |
| Compiled code (not fallback code) raising an uncaught exception | prints only the last traceback line | prints the full traceback | not implemented yet |
| A compiled module-level function used as a value in non-strict code and handed to CPython (`fn = (None, f, g)[k]`, `callback(f)`) | crosses as a `pycc.compiled_function` object (one per function) that takes positional arguments only; its `repr` and attributes are not a function's | a `function` object, which takes keywords too | not implemented yet: a keyword call raises `TypeError` |
| A compiled method looked up from CPython (`getattr(obj, "_process_IHDR")`) | a `builtin_function_or_method`; a private (`_name`) method is published only in non-strict mode and only when every parameter is an object | a bound method of a Python function; every method is an attribute | by design: a private method with native parameters is not callable from Python |
| A native specialization of a method that takes the integer attribute it reads first as a parameter (`self.bitdepth`, reported by `--report-fallbacks`) | reads the attribute once, when called | reads it at each use | not observable: the specialization runs only native code between the reads, so no Python code (other than a garbage-collection finalizer, which runs at no defined point) can change the attribute in between |
| A warning compiled code issues (`warnings.warn(...)` in non-strict code) | attributed to the nearest Python frame calling into compiled code (`<sys>:0` in a native program), so `stacklevel` and the printed file and line differ, and the default filter shows it once per such frame line | attributed to the frame `stacklevel` names | not implemented yet: compiled functions have no Python frame |
| `sys._getframe(n)` (and `inspect` frame walks) called from compiled code | counts only Python frames: compiled callers are skipped and a CPython-run class's method adds its one forwarder frame, so `n` names a frame further up the stack, or raises `ValueError` when the stack is shallower (pydantic 2.13.5's `Model[T]` parametrized at module level or in a function called from module level raises its own `RuntimeError: This function must be used inside another function`) | counts every function frame | not implemented yet: compiled functions have no Python frame |
| Non-strict mode: a CPython object used as a list, tuple or `str` index, a list store's index or a `range()` argument | read through `__index__`, as CPython does; a `range()` argument beyond 2**61 raises `OverflowError` | `range()` takes any `int` | rare: a compiled loop never counts that far; a sequence index of any size raises CPython's own `IndexError` |
| `open(0)` (the builtin `open`, file descriptor 0) | standard input itself, sharing one buffer with `input()` and `sys.stdin`; the descriptor stays open | a second text file over descriptor 0 with its own buffer, closing the descriptor when collected | rare: only a program that mixes `open(0)` with `input()` can tell |
| Non-strict mode: `o.sort(key=f)` / `sorted(o, key=f)` / `min(o, key=f)` on a CPython object `o` | the key function runs on each element while `o` is iterated, then the keys are sorted (or compared) by CPython; a receiver that is not a `list` raises after the keys are computed (`AttributeError`, or `TypeError` for an object with its own `sort`) | `sorted` iterates `o` fully before the first key call; `o.sort` looks the method up first | rare: only a key function with side effects, or an iterable that observes them, can tell |
| Non-strict mode: a CPython object passed to a typed `int`/`float`/`bool`/`str` parameter (or returned as one) | checked at the boundary: `TypeError: f() argument 1 must be int, not str`; an `int` for a `float` slot becomes a `float` | the body runs with the object and fails (or not) later | by design: typed code keeps native representations |
| Strict native build: an unannotated function or method (not `__init__`) | compiled with the one signature its call sites imply, like a private helper; `T0001` when the call sites disagree, none types a parameter, or the body does not pin the return | takes any value | by design (a strict-mode rule since v0.2): a native program is closed, so every caller is known. An `--ext` module's public functions still need annotations (`T0001`) |
| A module-level `if` testing `sys.gettrace()` (in a module that never names `settrace`) | the `else` branch, decided when compiling: compiled code runs no trace function | the branch for the tracer in effect when the module runs | by design: a compiled program cannot be traced |
| `x[k]`, `x[k] = v`, `del x[k]` on an instance (by `self` or a name bound only to calls of the class) of a module class defining `__getitem__`/`__setitem__`/`__delitem__` | `x.__getitem__(k)` and so on: an instance attribute named like the dunder is called | the class's method, looked up on `type(x)` | by design: no compiled class stores a dunder on an instance |
| Native build (strict or non-strict): an unannotated `def`, `name = lambda ...` or method that nothing in the entry module mentions (and the module reaches nothing by string: no `getattr`, `globals`, `eval`, ...) | not compiled, nor checked | binds the name | by design: it can never run, so the program's behavior is the same, and no call site could type it. An `--ext` module keeps every definition |
| Non-strict native build: an unannotated function called from compiled code with values of one type | compiled with that type (inferred from its call sites like a private helper's) | takes any value | by design; a function fallback code also calls is compiled with objects instead (or runs in CPython), and an `--ext` module's unannotated functions take objects (see the next row) |
| Non-strict `--ext`: an unannotated public function or method that loops, whose body implies `str`, `int` or `bytearray` for some parameters (indexed, sliced, `len()`, a `str` method; an index, slice bound, `range()` argument or integer arithmetic; an item used as a number, `s[i] - 1`, `(x + y) & 0xff` with `x = s[i]`, or stored one) | gets a native specialization: when every such argument's type is *exactly* `str`/`int`/`bytearray` (no subclass), it runs natively on a UTF-8 copy of each `str` and on each `bytearray`'s own buffer (its items read and stored in place, its size and buffer re-read after anything that may run CPython code); otherwise it runs on the CPython objects as before (`--report-fallbacks` lists `specialized:` and `not specialized:` functions). A `list`, `dict`, `set`, `tuple`, `bytes` or `memoryview` argument always takes the object path. A builtin call the original makes through CPython (`abs` of an object) is a native call in the specialization when its typed arguments allow | the same results and exceptions either way | by design: only immutable values are converted (a converted list would no longer share the caller's stores; a `bytearray` is not converted but shared); converting a `str` copies it once per call, and the module imports `builtins` under a hidden name for the guard. A module binding `type`, `str`, `int`, `bytearray` or `builtins` is not specialized; a specialization's native builtin call does not see a later reassignment of `builtins.abs` and the like |
| A `range` object kept in a variable or a list and only iterated (`r = list(map(range, xs))`, `for i in r[0]`), made from an argument that is not an `int` | compiled as its `(start, stop, step)` triple (`pycc_ast::desugar::range_values`): strict mode refuses a non-`int` argument when the triple is iterated; non-strict mode converts a CPython object argument (`__index__`) when it is iterated, so its `TypeError` is raised there | raises `TypeError` when the range is made | rare: every `int` argument behaves the same; any other use of the range keeps it a CPython object (non-strict) or a compile error (strict) |
| Non-strict mode: `range(a, b)` of two CPython objects whose conversions both fail (`range(1.5, len(None))`) | the first argument's conversion (`__index__`) runs before the second argument is evaluated, so its `TypeError` wins | every argument is evaluated, then converted | rare: only two failing arguments can tell |
| An `int` beyond 63 bits held by a `tuple` (`t = (x * 2, 1)`, `q, r = divmod(big, 7)`) | the tuple's reference to it is never released, so a long loop building such tuples grows memory | freed with the tuple | not implemented yet (D-182); temporaries, names, parameters, call arguments and returned values are reference counted (#625) |
| Non-strict mode: a name holding a native container (`xs: list[int]`, or a list built natively) passed into an `object` slot | compile error `T0021` (a display such as `f([1, 2])` and a local that only ever flows into objects are built as CPython containers instead; a fresh list nothing else holds yet -- a comprehension, `list(...)`, `sorted(...)`, `s.split()`, a concatenation, repetition or slice of scalars, `str`s, tuples of those or instances -- is copied into one, as an argument, a stored value or an operand of an operator on an object; a comprehension whose elements are objects builds a CPython list or set) | the same list object is shared | a copy would break aliasing; refused rather than copied |
| `itertools.dropwhile(pred, it)` | `pred` is called on every element | `pred` is not called again after it first returns false | rare: only a predicate with a side effect can tell; `takewhile` calls it exactly as CPython does |
| `int \| float` operands CPython accepts that pycc refuses | compile error: a tuple element of an `--ext` signature typed `int \| float` | runs | not implemented yet; tuples whose elements differ only in numeric kind compare by value (`(1, 2.5) == (1.0, 2.5)`), a `float` key finds the equal `int` key of a `dict[int, ...]` (`d[1.0]`), and a name, an accumulator, a list display, a list whose first binding (a display, `[x] * n` or a comprehension) later stores or appends the other kind, and a dict display's values become `int \| float`, and an `int \| float` index or `range()` bound raises CPython's `TypeError` when it holds a `float` |
| `"...".format(args)` with a `{}` or `{!s}` field | `str(arg)` | `format(arg, "")` | the same for every value without its own `__format__` (no compiled class has one) |
| Non-strict mode: `format(o, spec)` (and `f'{o:spec}'`) of a class object, `o` a type (`f'{str:}'`) | calls `o.__format__(spec)`, the class's unbound method: `TypeError` | `type(o).__format__(o, spec)`: `<class 'str'>` | rare: formatting any other object, or a class with no format spec (`f'{str}'`), behaves as in CPython |
| `reversed(xs)` | returns a new list | returns a lazy iterator | equal output wherever the result is only iterated, indexed by `list()` or printed via `list(...)` |
| `str` character classes beyond ASCII (`isdigit`, `isspace`, `split()` whitespace, case mapping) | Rust's Unicode tables | CPython's Unicode database | they agree on ASCII; rare differences beyond it |
| `sum()` of an empty `list[float]` | `0.0` | `0` (the int start value) | not planned until `sum` gets a start argument |
| `map(f, xs)` / `filter(f, xs)`, and `zip(...)` other than in `for a, b in zip(...)` with one target per argument | build a list eagerly (`pycc_ast::desugar`) | return lazy iterators | equal output wherever the result is iterated, unpacked or passed to `list`/`sum`/... and the inputs do not change meanwhile; printing the map object itself differs, and a list the loop body grows or shrinks is not seen (`for t in zip(xs, ys): xs.append(...)`) |
| `sys.stdin.buffer.readline` aliased by a module-level name (`input = sys.stdin.buffer.readline`) whose every call is converted to numbers at once (`int(input())`, `float(input())`, `map(int, input().split())`, `[int(x) for x in input().split()]`) | read as text, natively | reads `bytes` | equal for every input `int()`/`float()` accept as ASCII; a non-ASCII digit (`int(b"\xd9\xa1")`) is accepted from text but refused from `bytes`. Any other use of `sys.stdin.buffer` is `bytes`: CPython's own binary stream, read through the `sys` module |
| `sys.stdin`/`sys.stdout` stream calls (`readline`, `read`, `readlines`, `write`, `flush`) and `sys.setrecursionlimit` | native (`setrecursionlimit` is a no-op: compiled code recurses on the native stack) | `sys` module objects | same output; other `sys` attributes still go through CPython. Whenever CPython is present (`--ext`, or an embedded build) every native read and write, `print` and `input()` included, goes through CPython's `sys.stdin`/`sys.stdout`, so native and Python-side I/O share one buffer |
| A reference cycle between lists, dicts, sets, class instances and/or exceptions (`a.other = b; b.other = a`, `xs.append(xs)`, `raise e from e`), including one that passes through a CPython object an instance's `object` attribute holds | never freed: compiled `str`, `list`, `dict`, `set`, class instances and exceptions are reference counted with no cycle collector, so a cycle's objects keep each other alive until the process exits | the cycle collector frees it once unreachable | on purpose for this release; a non-cyclic object is freed at the moment its last reference goes, exactly when CPython frees it |
| `__del__` on a compiled class | never called | called when the reference count reaches zero | not implemented yet: a compiled class's `__del__` is an ordinary method nothing calls |
| A value of an exception class that defines its own `__init__`, built by calling the class (`err = Owned(3)`; such a class cannot be raised by compiled code) | never freed | freed when its last reference goes | not implemented yet: a raised or caught exception, its message, cause and group members, and a bridged CPython exception are reference counted and freed when the last reference goes |
| `d.keys()`, `d.values()`, `d.items()` | a new list (a snapshot) | a live view (`dict_keys([...])` when printed) | equal output wherever the result is iterated, indexed through `list(...)`, sorted or measured; printing the view itself differs |
| `str` hashes in an `--ext` module when `PYTHONHASHSEED` is unset | compiled code draws its own random SipHash key, so a set of `str` built natively and one built by the host interpreter may iterate in different orders within one process | one per-process key | both are randomized, so no program can depend on either order; with `PYTHONHASHSEED` set, `str` hashes (and a set of `str`'s iteration order) are exactly CPython's |
| `==`/`!=` between containers of class instances (`set[C]`, `list[C]`, a dict with `C` values, nested) | compile error `T0021` | compares elements with the class's `__eq__` | not implemented yet |
| Replacing a `dict`'s keys while iterating it without changing its size (`del d[k]; d[k + 10] = 0` inside `for k in d`) | iteration continues over the changed table | raises `RuntimeError: dictionary keys changed during iteration` once it runs past the keys it started with | not implemented yet; a change of size raises CPython's `RuntimeError: dictionary changed size during iteration` (`Set changed size during iteration` for a set) at the next step, as in CPython |
| A name rebound to an unrelated value (`n = input()` then `n = int(n)`, or an unannotated parameter `def f(n): n = int(n)`) | each live range is its own variable (`pycc_ast::desugar::webs`), so the earlier value is released when its own variable is next rebound or its scope ends | the earlier value is released at the rebinding | on purpose: it is what lets each live range have its own type; output is the same, only the moment a value is freed differs |
